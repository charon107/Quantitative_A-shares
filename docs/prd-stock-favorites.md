## 1. 背景与问题

当前看板查看个股的唯一路径是：进入「个股查询」页 → 在搜索框输入代码/名称 → 点击结果。对于用户长期跟踪的股票（持仓、观察名单），每次都要重复搜索，路径长、成本高。

用户原话："收藏后的股票我可以直接查看"。核心诉求是**缩短"打开常用股票"的路径**。

## 2. 目标与非目标

### 2.1 目标

- 用户可以将任意股票加入/移出收藏，操作不超过 1 次点击。
- 用户可以在 1 次点击内从任意页面到达收藏列表，再从列表 1 次点击打开个股详情。
- 收藏数据在浏览器端持久保存，刷新、关闭浏览器后不丢失。

### 2.2 非目标（本期不做）

- 多设备同步、账号体系（当前为个人看板，无登录）。
- 收藏分组/标签、自定义排序、备注。
- 收藏股的批量行情提醒、涨跌幅预警。
- 收藏股在大盘概览页的聚合展示。

## 3. 用户故事

| # | 用户故事 | 优先级 |
|---|----------|--------|
| US-1 | 我在查看某只股票时，可以一键收藏，下次想看时不用再搜索 | P0 |
| US-2 | 我可以随时打开收藏列表，看到所有收藏的股票及其最新价/涨跌幅 | P0 |
| US-3 | 我点击收藏列表中的股票，直接跳转到该股的详情页 | P0 |
| US-4 | 我可以取消收藏，列表立即更新 | P0 |
| US-5 | 收藏状态在页面上清晰可见（已收藏 vs 未收藏） | P1 |

## 4. 入口方案对比与推荐

用户明确提出"不清楚入口应该是怎么样的"。结合现有信息架构（顶部 tab 导航：大盘概览 / 个股查询 / 排行榜 / 基本面选股 / 多头时长 / 数据状态），评估三个方案：

### 方案 A：顶部导航新增「我的收藏」tab（✅ 推荐）

- **做法**：`App.tsx` 的 `PAGES` 中新增一项，作为独立页面承载收藏列表。
- **优点**：与现有 IA 完全一致，发现成本最低；任意页面 1 次点击可达；页面空间充足，可展示行情信息，后续可扩展分组。
- **缺点**：tab 栏多一项（当前 6 项，加 1 项仍可接受，导航已支持横向滚动）。

### 方案 B：嵌入「个股查询」页顶部

- **做法**：在搜索框下方放一条收藏股的横向快捷条。
- **优点**：不增加导航项；搜索场景下顺手。
- **缺点**：必须先进入「个股查询」页才能看到，路径仍是 2 步；空间受限，只能做"快捷 chips"，放不下行情信息；与"直接查看"的诉求不完全匹配。

### 方案 C：搜索框下拉集成收藏

- **做法**：`SearchBox` 聚焦且未输入时，下拉默认展示收藏列表。
- **优点**：零新增 UI 元素。
- **缺点**：入口隐蔽，发现成本最高；与"直接查看收藏列表（含行情）"的诉求不匹配。

**推荐：方案 A 为主入口，同时把方案 C 作为增强（P2，可选）：搜索框空输入聚焦时优先展示收藏股。** 方案 B 不采用。

## 5. 功能需求详述

### 5.1 收藏 / 取消收藏（P0）

- **触发位置**：「个股查询」页，股票名称与代码旁（`StockQuery.tsx` 第 66–71 行的名称区域）放置星标按钮（☆/★）。
- **行为**：
  - 未收藏：点击 ☆ → 立即收藏，图标变 ★（填充色用主题色 `clay`），轻提示"已收藏"。
  - 已收藏：点击 ★ → 立即取消，图标变 ☆，轻提示"已取消收藏"。
- **可见条件**：仅当已加载出个股数据（`kline.data` 存在）时显示，无股票选中时不显示。
- **反馈**：图标即时切换，无确认弹窗（收藏是低成本可逆操作）。

### 5.2 收藏列表页（P0）

- **入口**：顶部导航「我的收藏」，位置建议放在「个股查询」之后。
- **列表内容**（每行一只股票，复用 `HotStocks.tsx` 的行样式与排版语言）：
  - 股票名称 + 代码
  - 最新价、涨跌幅（带红绿着色，复用 `fmtPrice` / `fmtPct` / `signClass`）
  - 行尾取消收藏按钮（悬停显示的 ✕ 或星标切换）
- **排序**：按收藏时间倒序（最近收藏在最前）。
- **点击行为**：点击行 → 复用现有 `openStock(code)` 跳转「个股查询」并载入该股；来源记为收藏页，提供"返回我的收藏"。
- **空状态**：无收藏时展示引导文案："还没有收藏股票。在个股查询页点击 ☆ 即可收藏。"并附跳转「个股查询」的按钮。
- **加载/失败态**：复用现有 `Loading` / `ErrorState` 组件。

### 5.3 搜索框收藏增强（P2，可选，可后置）

- `SearchBox` 聚焦且输入为空时，下拉展示收藏股列表（名称 + 代码），点击直接选中。
- 输入内容后恢复现有搜索逻辑，不受影响。

## 6. 数据存储方案

### 推荐：localStorage（纯前端，无后端改动）

- **存储键**：`favorites:v1`
- **数据结构**：
  ```json
  [{ "code": "600519.SH", "name": "贵州茅台", "addedAt": 1753257600000 }]
  ```
  冗余存 `name`，列表在行情接口未返回时也能先渲染名称。
- **读写**：封装一个 `useFavorites` hook（读、增、删、判断是否已收藏），所有组件通过 hook 操作，不直接碰 localStorage；hook 内部用 `useSyncExternalStore` 或自定义事件保证跨组件状态同步。
- **行情数据**：列表页拿到收藏的 code 数组后，调用后端批量行情接口获取最新价/涨跌幅。

### 后端改动（唯一一项，小工作量）

现有接口只有单 code 全量 K 线（`GET /api/stocks/{code}/kline`，见 `src/api/routes/stocks.py:18`），用于列表太重。需新增一个轻量只读接口：

- `GET /api/stocks/quotes?codes=600519.SH,000001.SZ`
- 返回每只股票的最新交易日收盘价、涨跌幅（DuckDB 单条 SQL 按 code 分组取最新行即可）
- 未命中的 code 不出现在结果中，前端显示"—"

### 为什么不上后端存储

- 当前系统无用户体系，上后端等于引入"设备标识"或账号问题，成本远大于收益。
- 个人看板主要在固定浏览器使用，localStorage 足够。
- 未来若引入账号体系，可加同步层，数据结构保持兼容。

### 边界与异常

| 场景 | 处理 |
|------|------|
| localStorage 数据损坏（JSON 解析失败） | 当作空列表处理，不抛错 |
| 收藏的股票已退市/行情接口查无此 code | 行内显示"—"，不阻塞其他行 |
| 收藏数量上限 | 不做硬限制；超过 200 只时列表页正常展示（量极不可能达到） |
| 隐私模式 localStorage 不可用 | 降级为会话内存态，页面刷新丢失，功能不报错 |

## 7. 埋点/度量（可选）

个人项目可不接埋点，用以下问题验收即可：

- 收藏操作是否 ≤1 次点击完成？
- 从任意页面到打开一只收藏股详情是否 ≤2 次点击？

## 8. 验收标准

1. 在个股查询页对任意股票点击 ☆，图标变 ★；刷新页面后 ★ 状态保留。
2. 顶部导航出现「我的收藏」，点击进入后能看到刚收藏的股票，含名称、代码、最新价、涨跌幅。
3. 点击列表中的股票，跳转到个股查询页并正确加载 K 线；返回键可回到收藏页。
4. 在收藏页或个股页取消收藏后，列表立即移除该项。
5. 空收藏时列表页展示引导空状态，不报错。
6. 断网/接口失败时收藏列表页展示错误态而非白屏。
